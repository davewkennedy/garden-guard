## Hard rules
- NO build tools, NO npm packages, NO ES modules (`import`/`export`): index.html must work when
  double-clicked (file://). Plain <script> tags, each file defines ONE global.
- Each file has ONE owner. Only edit your own files. Need something in another file? Message its owner
  (or Hank). Announce before editing anything shared (only index.html / style.css, both Hank's).
- game.js, data.js, autopilot.js must NOT touch the DOM/window: they must run in Node too.
  End them with:  if (typeof module !== 'undefined') module.exports = <Global>;
  In Node they're loaded in order: data.js, game.js, autopilot.js (Dale's tools/ load them via require
  and put them on globalThis).
- Keep the C++ names (camelCase, drop trailing `_`): Game.update(dt), pickTarget, focusFire, waves(),
  isUnlocked, etc. Enums become frozen objects / string constants with the same names.
- World coordinates are logical pixels, TILE = 64, exactly as in C++.
- Saves: localStorage, keys prefixed "ggweb:"; always wrap in try/catch.
- Write a 5-10 line log in notes/<yourname>.txt (what's done, what's left, API you expose).

## Interfaces (agree on these; extend in your notes if needed)
- Game: `new Game()`; `reset(startMap=0)`; `update(dt)` (seconds, dt <= 0.05, called `speed` times per
  frame like MainWindow::tick); public fields as in game.h (towers, enemies, projectiles, coins, lives,
  phase, mapIndex, cols, rows, W, H, ...). Signals -> tiny emitter: `game.on(name, fn)`, internally
  `this.emit(name, ...args)`. Same signal names as game.h (shot, killed, leaked, placed, upgraded, sold,
  waveStarted, waveEnded, mapCleared, mapStarted, won, lost, bugSound, wildcard, gust).
  Settings the C++ reads from QSettings (difficulty, unlocks, journal) -> Bill exposes plain fields/
  methods; UI/Boomhauer persist them in localStorage.
- View (Bobby): owns the camera for the board canvas. `View.resize(cssW, cssH, dpr, game)` fits the
  whole map (like setupScale); `View.zoomAt(screenX, screenY, factor)`, `View.panBy(dx, dy)`,
  `View.reset()`, `View.screenToWorld(x, y) -> {x, y}`, `View.worldToScreen`. Clamp zoom to
  [fit, fit*4] and keep the map on screen.
- Renderer (Bobby): `Renderer.draw(ctx, game, view, ui)` where ui = { hoverTile, selection,
  placingType, rangePreview, time, ... } (Hank passes; tell Hank what you need). All the seasons,
  weather, terrain, sky lanes, fire points, reticles, boss bar, FX.
- Input (Hank): pointer events on the canvas. Tap = click, double-tap = double-click (focus fire),
  long-press = hover/info, 1-finger drag when zoomed = pan, 2-finger pinch = View.zoomAt.
  Mouse wheel = zoom on PC. Keyboard shortcuts as in Qt.
- Sfx (Boomhauer): `Sfx.unlock()` (call on first pointerdown), `Sfx.play(name)`, `Sfx.muted`.
  Same synthesized sounds as audio.cpp.
- Autopilot (Dale): `new Autopilot(game)`, `step()` called each frame like the C++.

## Enum and naming rules (added 14:40, binding for everyone)
- Enums from data.h live on DATA: e.g. DATA.Projectile.Mortar, DATA.Season.Winter. Enums that the C++
  uses as array indices (EnemyType, tower types) stay INTEGERS in the same order; all other enums are
  frozen objects whose values are their name strings: DATA.Projectile = {None:'None', Mortar:'Mortar', ...}.
  Terrain kinds: DATA.TERRAIN_WATER etc., same values as C++.
- Enums from game.h live on Game as statics: Game.Phase.Build ('Build'), Game.Difficulty.Easy (0/1/2,
  integers), Game.EffectKind.Hit ('Hit').
- Constants from game.h: Game.FIRE_POINT_RADIUS, Game.AMBUSH_BONUS.
- Methods that return a pointer in C++ return the object or null in JS (towerAt, getTower, pickTarget,
  placeTower). Methods taking `const Tower &t` take the tower object.
- QPointF becomes {x, y}. QString becomes a string. std::optional becomes null when empty.
- Strings with emoji: copy them exactly from the C++ source.
